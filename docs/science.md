# Numerical methods and reproducibility

The GUI and MCP adapter call the same functions in [science.py](../afm_workbench/science.py). Standard plane/polynomial leveling, explicit-method line alignment, statistics and profiles use the [native Gwyddion C backend](../native/README.md); Python handles validation, coordinates, invalid pixels and provenance; custom terrace and three-point operations use NumPy. All numerical outputs remain in the imported channel's calibrated value unit. A phase channel's dispersion is an angular dispersion; it is not height roughness. Display range and colour map never enter a numerical recipe.

## Coordinates, regions and invalid data

Normalized coordinates describe the full scan footprint, with top-left `(0, 0)` and bottom-right `(1, 1)` in the imported display orientation. A pixel centre is `((column + 0.5) / width, (row + 0.5) / height)`. A rectangular region includes centres satisfying its lower bounds and excludes centres on its upper bounds. A full `(0, 0, 1, 1)` region includes every pixel. Recipes accept full-resolution binary `mask` matrices and `masking: include | exclude | ignore`. A rectangle alone acts as the mask; with a raster mask it restricts the region in which that mask is evaluated. With neither selection, all finite pixels participate. Scan-angle rotation is not implemented.

NaN represents an invalid pixel: it is excluded from fitting/statistics and preserved in processed arrays. Empty references and infinite values are rejected. The recipe is replayed from a copied source array; it never modifies its input. Operation history records version, normalized reference, fit model, and pre/post statistics. The service associates that history with source calibration and checksum.

### Editable masks and display state

Each image has a persistent binary mask in its original stored pixel grid. Rectangle edits use the pixel-centre convention above. Brush strokes select pixels by distance to the stroke in source-pixel coordinates, with a radius in source pixels; the footprint therefore follows the image's pixel sampling rather than imposing an isotropic physical length. Threshold edits use inclusive calibrated value bounds on the current saved numerical result at full resolution. Mask values are a selection, not replacement heights, and their blue overlay is display-only. On a reduced display, an overlay cell is marked if any source pixel within it is marked, so small exclusions remain visible; calculations still use the exact original-resolution selection.

The GUI applies the selected include/exclude/ignore mode to fits, area statistics, profiles and both step-height regions. An Area selection intersects the raster selection. No valid selected pixels produces an explicit empty-selection result or error, never an unmasked substitute. Mask edits and their undo/redo history are separate from processing history. The service resolves a saved-mask request into a full-resolution binary snapshot before recording a recipe or measurement; editing the current mask cannot change that earlier result. Manifests include the current mask and display settings alongside the numerical history.

Color limits and histograms use finite, full-resolution numerical values, independently of the mask. Full range uses the extrema; percentile range trims the requested fraction from each tail; Area range uses the rectangle's values. Numeric limits must be finite and strictly increasing. A constant-valued image receives a nonzero display span without changing its data. Manual limits stay fixed across Original/Result comparisons; automatic limits are recalculated for the viewed data. Palette and range settings persist per image and never enter scientific recipes, statistics or CSV arrays.

## Corrections

New GUI plane corrections use `{"type":"plane","method":"gwyddion"}`. The least-squares slopes are fitted to selected finite pixels, then subtracted about Gwyddion 2.71's pixel-index pivot `(width/2, height/2)`. The fitted height intercept is retained. This pivot is half a pixel past the mean pixel index, so the mean can change by half the sum of the two pixel slopes. Use Zero mean separately to choose a zero datum. History records both the fitted coefficients and the actually subtracted plane in normalized pixel-centre coordinates. At least three non-collinear reference pixels are required.

`polynomial` subtracts the entire least-squares polynomial background using Gwyddion's native fit/subtraction routines. `mode: independent` uses every product through `degree_x` and `degree_y`; `mode: total` includes terms whose combined degree is at most `degree`. Defaults are independent degrees 3 and 3; degrees 0–11 are supported. The native monomial basis spans −1…1 at the first/last pixel centres. History records the basis, terms and coefficients. Python checks reference geometry without fitting data. Degenerate references and detected native factorization failures are rejected. A degree-one independent polynomial includes `x*y`, so it is not the same as a plane. [Gwyddion's leveling documentation](https://gwyddion.net/documentation/user-guide-en/leveling-and-background.html) explains these polynomial spaces and the risk of removing real surface structure.

Alignment accepts an explicit `method`: `median` (the GUI default), `median_difference`, `modus`, `matching`, `polynomial`, `trimmed_mean`, `trimmed_difference`, or `facet_tilt`. `mean` is a convenient degree-zero polynomial alias. `align_rows` and `align_columns` choose a stored-array axis; `align_scan` resolves recorded scan direction or takes an override. Both orientations use the same implementation. The polynomial degree is 0–5 (default 1); each trimmed tail defaults to 0.05. Gwyddion's median selects the upper middle value for even counts. Offset methods centre shifts by their arithmetic mean, while difference methods also remove the affine trend from accumulated shifts. Polynomial alignment subtracts each fitted line polynomial and restores the original image mean. Facet tilt removes line slopes without aligning offsets.

Matching weights use the numerical height values in base SI units, requiring conversion from the displayed channel unit; facet convergence uses calibrated lateral spacing in the same units as height. Support counts, shifts or polynomial coefficients, convergence and fallback warnings are recorded. See the [complete comparison and deliberate differences](gwyddion-compatibility.md), including Gwyddion's masked-difference bug and insufficient-reference behavior.

The GUI's **Zero reference → Mean / Minimum / Maximum** actions (`zero_mean`, `zero_min`, `zero_max`) use Gwyddion's masked statistic and constant-shift routines to subtract the selected reference's mean, minimum or maximum from all pixels.

**Saved-recipe compatibility:** `plane`, `align_rows`, `align_columns` and `align_scan` without `method` retain their prior numerical behavior. The old plane removes the fitted intercept; old independent alignment centres NumPy medians by their median; old adjacent differences use a median-zero cumulative shift. New GUI actions always write an explicit method. MCP clients should do the same. Original arrays and previous runs remain unchanged.

## 2D material automatic mode v2 (up to three planes)

`auto_2d` separates three contributions: scan-line background, terrace reference planes, and local topographic features/roughness. It does not require all pixels to sit on ideal planes. Numerical output is the original calibrated array minus recorded line offsets and **one reference plane**. No smoothing, per-terrace zeroing or removal of particles is applied to the output. GUI and MCP use this same versioned implementation in [auto_processing.py](../afm_workbench/auto_processing.py).

### Processing and reference selection

1. When enabled, resolve the fast scan axis from the TIFF metadata (or explicit override). Estimate adjacent-line median offsets and retain the median linear increment for subsequent plane leveling. Preserve unusually strong, coherent full-line boundaries: they can be physical steps or acquisition jumps. The detector uses an eight-MAD local-innovation threshold, a four-texture-sigma floor, and 95% coherence. This is a heuristic, not proof of an artifact's origin.
2. Estimate within-line texture from locally detrended segments, between 8 and 128 pixels depending on image width. This estimates correlated texture more broadly than pixel-to-pixel detector noise. Local detrending is used only for estimation.
3. Provisionally remove robust local tilt and segment connected plateaus on a median grid no larger than 64 × 64. Adjacent grid cells connect below the larger of 2.5 texture sigma and twice the 90th-percentile local grid difference. Major regions need at least 32 reference pixels and 1% of the selected reference. Small local features can remain outside fitting support.
4. Robustly fit independent planes to these spatial regions, with up to 30 rejection/refit iterations and at most 32,768 deterministic samples per region. Merge compatible disconnected regions whose predicted planes agree across the footprint within four texture sigma. Reject fragmented support or more than **three distinct fitted planes**.
5. Validate every reference pixel at full resolution. Require at least 90% supported pixels; reject a coherent unexplained region larger than 1.5% of the reference. Per-plane tile-median spans must remain within three robust residual/texture sigma. These are disclosed quality heuristics, not instrument uncertainty bounds.
6. Subtract the tilt of the **largest supported plane** from the entire image and set the supported median to zero. Other terrace height and tilt differences remain. The largest plane is a reproducible reference choice, not an identification of the substrate.

This follows the general AFM practice of selecting flat reference regions and excluding particles/step edges when estimating a background. [Gwyddion's leveling documentation](https://gwyddion.net/documentation/user-guide-en/leveling-and-background.html) describes masked/facet leveling and warns that background subtraction can remove real surface structure. [Its terrace analysis](https://gwyddion.net/documentation/user-guide-en/feature-measurement.html) separates terrace segmentation from background fitting. This custom automation is not equivalent to Gwyddion Flatten Base, Facet Level or Terrace Analysis. Its numerical behavior remains unchanged in the compatibility revision; synthetic tests check its own stated model. No equal atomic step height or material-layer identity is imposed.

### Inspectability, failure and limits

The GUI saves a successful correction immediately. Fitted-plane details report reference coverage and fit-reference residual RMS; **Inspect fitted planes** displays the removed background (including line correction) and full-resolution-derived fitting assignments. Dark mask pixels are excluded from fitting but retained in numerical output. Compare with **Original** and use **⌘/Ctrl Z** or Record's undo to restore the previous recipe. Applying the terrace correction preserves manual color limits, or recalculates the selected automatic/full display mode for the corrected values; neither choice changes data. History records the axis/source, line offsets, preserved boundaries, plane coefficients, chosen reference, masks, sampling, gates and algorithm version. The service also offers an unsaved preview command for API/MCP clients.

**Correct scan-line background** can be switched off. Variation shared by an entire scan line is not uniquely separable into instrument drift and real topography from one height map. Strong coherent steps are guarded, but smaller or nonuniform full-line features and true slow-axis curvature can still be removed. Use plane-only mode or an explicit manual reference when preserving that shape matters. Unknown scan axes require an override when line correction is enabled. Missing references, weak support, too many planes or failed quality gates leave the saved analysis unchanged and open the manual-leveling path.

The original `terrace_plane` v1.1 operation remains unchanged for exact replay of older recipes. It fits one to three parallel planes by height clustering and requires residual RMS within 1.5 times a local difference-based noise estimate. The real-sample tests showed that this earlier operation was too restrictive and sensitive to initialization; **Prepare → More corrections → Fit up to 3 terrace planes** creates an `auto_2d` v2 correction. The default opening workflow uses `auto_characterize` v1 as described below. Corrections apply to the current saved result, so undo an existing Auto level step before fitting terraces from the original data.

## Automatic characterization and three-point leveling

The user's 2026-11-11 workflow decision is: open Z height → align rows/columns, optionally masked → level using three points on one plane → reveal flake outlines → drag a rectangle for local terrace/particle contrast; notify the user when reference selection fails. The implementation in [characterization.py](../afm_workbench/characterization.py) is a custom deterministic proposal, not a material classifier or a validated physical-plane identification.

`auto_characterize` v1 reuses the `auto_2d` v2 detector and its 1–3-plane support gates above. It applies its optional scan-line offsets first, then searches the largest supported plane for clean 5 × 5 pixel patches. Up to 24 × 24 candidate centres are tested in stored-array coordinates. Every pixel in a candidate patch must be valid, permitted by the reference mask, assigned to that plane, and within three texture sigma of its robust fit. The farthest pair of centres and a third centre maximizing triangle area define three patch means. If that plane is unusable, the next largest is tried.

The actual subtracted plane passes through the three means at their valid-pixel centroids. It must have a normalized triangle double-area of at least 0.02, design-matrix condition number at most 100, and agreement with the independently fitted many-pixel plane at all four image corners within three texture sigma (or the floating-point floor). A three-point fit has zero residual at its vertices by construction; that alone is never the acceptance test. One reference plane is subtracted globally, preserving other terraces' relative heights and slopes. The zero datum is this plane, not the image median. Reference patches, means, pixel bounds, coefficients, mask snapshot, axis source, offsets, detector version, gates and selection checks are recorded. Source heights are never filtered.

Only this new operation applies a recorded quantization floor to detection: one relative machine epsilon at the maximum calibrated value minus calibration intercept for a recorded floating-point source, or half the calibrated raw-value increment for an integer source. The floor avoids treating source rounding as extra surface structure. It is not a measurement uncertainty estimate; old operations retain their previous behavior.

`three_point` v1 is the manual fallback, available through the GUI and the same recipe API/MCP. It accepts three normalized `[x, y]` coordinates and an optional integer `radius` from 0 to 32 (default 2). Square patches are clipped at image borders; only valid, unmasked reference pixels contribute. Empty patches and poorly conditioned triples are rejected. Membership in a common physical plane is the user's choice in this manual operation. It performs no implicit line alignment: use the row/column controls first when necessary.

With **Auto level new height images when opened** enabled (the default), opening an unprocessed calibrated height image applies and saves this correction; existing recipes are left as saved. The confirmation message offers **Undo**, and **⌘/Ctrl Z** or Record's undo restores the previous recipe. A failed automatic fit leaves the saved recipe unchanged and displays a persistent notice with manual point selection. Failure can reflect unknown scan direction, inadequate mask coverage, too many planes, curvature, or unreliable point placement. Success is a proposed reference, not proof that it is the substrate. Line alignment retains the physical ambiguity described above.

Successful Auto level and 3-point level actions also save a separate 2% percentile contrast to make outlines visible. The Contrast rectangle then uses the finite minimum and maximum of the selected full-resolution ROI on the viewed Result or Original data. It neither changes pixels nor participates in any fit. Display settings remain separate from the numerical recipe and can be adjusted in View; undoing a correction restores its prior recipe, not earlier contrast settings. The rectangle identifies a viewing region only: the application does not label it as a terrace or dirt.

[Gwyddion's three-point leveling documentation](https://gwyddion.net/documentation/user-guide-en/leveling-and-background.html) describes subtracting a plane through three user-chosen reference locations. This automatic selection and square-patch implementation is custom NumPy code, not a claim of Gwyddion numerical equivalence. Executed checks and remaining limitations are in [validation](validation.md#characterization-workflow-2026-11-11).

## Scan-direction-aware alignment

`align_scan` resolves the fast-scan lines from Park's axis-swap flag in the untransformed stored array: rows without swap, columns with swap. Scan angle describes scanner orientation, not a rotation applied to this array. Forward/backward and up/down affect traversal, not which array axis contains a line. This interpretation follows the header and swap handling in [Gwyddion's Park importer](https://github.com/cbuehler/gwyddion/blob/master/modules/file/psia.c); swapped-axis instrument data still needs independent real-data validation. Existing catalogs already preserve the needed flags, so no reimport is required.

Missing or transformed orientation requires an explicit `axis: "rows"` or `"columns"` override. The chosen axis, source and original orientation are recorded. New alignment uses the selected Gwyddion method described above. Legacy `align_scan` recipes without a method still accumulate adjacent median differences with a median-zero datum and require three shared finite reference pixels in every adjacent pair.

The GUI's **Scan lines** controls apply and save alignment immediately. Selecting another method replaces the current explicit line correction, and **Off** removes it; undo restores the previous recipe. A step occupying most or all of a line is ambiguous with an acquisition offset and can be removed, so users should select a continuous reference strip when available and inspect the result. This caution is consistent with [Gwyddion's scan-line correction guidance](https://gwyddion.net/documentation/user-guide-en/scan-line-defects.html).

## Measurements

The statistics function reports mean, upper-middle median, minimum, maximum, count, variance, `Sa = mean(abs(z - mean(z)))`, `Sq = sqrt(mean((z - mean(z))²))`, skewness and **excess** kurtosis (subtract 3). `Sp = max - mean`, `Sv = mean - min` and `Sz = max - min`; the existing `peak_to_valley` field is an alias of `Sz`. Constant data returns zero skewness and excess kurtosis, following Gwyddion. These are population statistics over finite selected pixels, optionally intersected with an included/excluded mask; no plane is implicitly removed. They do not include spatial statistics such as surface area or autocorrelation. [Gwyddion's statistical analysis guide](https://gwyddion.net/documentation/user-guide-en/statistical-analysis.html) supplies the definitions.

Profiles default to Gwyddion Profile-tool automatic resolution and linear (bilinear in 2D) interpolation; nearest interpolation is also available. `sampling: legacy` retains the earlier automatic sample count, and explicit `samples` overrides either resolution rule. Width 1–128 pixels uses the Gwyddion continuous-coordinate transverse averaging convention. Within the outer half-pixel border the nearest centre is extended. Distances use the calibrated scan footprint in micrometres. Endpoints, count, interpolation, averaging width, masks and contributing samples are recorded. Invalid or fully excluded samples remain JSON `null` at their original distances; Gwyddion instead omits masked samples. No missing value is silently replaced with zero.

Step height is the signed mean of region B minus the mean of region A, on the current input surface. The two regions must not share pixel centres. Each region retains its statistics and coordinates. Their Sq values describe within-region dispersion and are **not** instrument uncertainty or an error bar on the step. Plane fitting, mechanism inference and model fitting are not implicit in this measurement.

## Validation performed by the test suite

[Synthetic tests](../tests/test_science.py) cover known plane removal, reference-limited fits preserving a step, row and column offset correction with retained features, missing references, NaN handling, analytical bilinear profiles, signed step height, statistical definitions, immutable source arrays and exact recipe replay. Run `python -m unittest discover -s tests -v` from a fresh checkout after installing dependencies and [building the native backend](../native/README.md).

The compatibility tests additionally compare stored synthetic outputs from selected Gwyddion 2.71 C functions executed through a temporary adapter. [Reference provenance and regeneration](gwyddion-compatibility.md) distinguish this numerical evidence from a full Gwyddion GUI or instrument-calibration validation. These checks do not establish calibration accuracy or quantify experimental uncertainty.
